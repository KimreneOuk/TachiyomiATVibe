# Test Reliability Preflight — Purge/Retain Audit

**Scope:** 7 candidate classes in `app/src/test` (JVM unit tests). Read-only: no source, test, build, or git changes; no Gradle/device runs. All claims below are **source-verified against the working tree at audit time**; no runtime behavior was demonstrated or claimed.

**Method:** every candidate was read in full; every cited production contract was opened and compared; test infrastructure config (Gradle + buildSrc + junit-platform properties) was inspected; the on-disk JUnit XML evidence was parsed.

1. **The on-disk "all green" evidence does NOT cover any candidate class.** `app/build/test-results/` holds 30 XMLs: `testDevDebugUnitTest` = 25 suites (timestamped 2026-10-13T06:37), `testStandardDebugUnitTest` = 5 suites (2026-10-13T17:11). Every suite is an OCR/Paddle/EngineLane/presentation class (`PaddleOcr*`, `BoxGeometryTest`, `DbPostProcessTest`, `EngineLane*`, `TranslationSheetAdvancedViewPreferenceTest`, …). **Zero of the 7 candidate classes appear.** The 0-failure/0-error baseline is true but irrelevant to this purge decision; it must not be cited as "candidates pass at baseline."
2. The single skip is `PaddleOcrDynamicPageBatchPolicyTest` (1 of 7, asset assumption) — unrelated to any candidate.
3. The quarantine mechanism is **live config but empty**: `buildSrc/src/main/kotlin/mihon/buildlogic/ProjectExtensions.kt:113-128` excludes tag `quarantined-flaky` unless `-PincludeQuarantinedTests` is set — and **no class in the repo currently carries that tag**. Nothing is being hidden from standard runs; the former quarantine of `BatchDispatchResumeWiringTest` was fully lifted.
4. **No parallel test execution is configured in-repo**: no `junit-platform.properties` in any source set, no `maxParallelForks`, no `forkEvery`, no parallel-mode system properties. `configureTest()` only sets `useJUnitPlatform { excludeTags(...) }` + logging. Scope caveat (v2): this rules out parallelism **under the default task invocation only** — JUnit platform parameters can still be injected externally (command line, `gradle.properties`), and sequential execution does not by itself prove that every asynchronous publisher finishes before a later test's global swaps; drain-before-restore was **not exhaustively verified** in this audit. Load-bearing for §1 rows 3/6 and §2.
5. Commit `581c5bf` (cited in `MangaScreenModelTranslationDrawerTest` line 78) is **not resolvable in local git history**; the production fix it describes is nonetheless **source-verified present** (see §5).

## 2. Cross-cutting risks (discovery / tag / config / async cleanup)

- **Global mutable state inventory** — exposure depends on execution mode (**v2 model**): **forked-JVM parallelism (`maxParallelForks`) does NOT share these** — each fork is a fresh process — whereas **in-JVM concurrent test methods** (JUnit platform parallel mode) race all of them directly. Also: `@BeforeEach`/`@AfterEach` resets do **not** make singleton-mutating tests safe under overlapping methods — a reset can land between another method's arrange and assert:
  1. `TranslationPipelineDiagnostics.{sink, detailedTracingEnabled, idGenerator, identityKeys}` (TranslationSchedulerTraceTest; also other diagnostics tests exist).
  2. Voyager `ScreenModelStore` dependency map + `ArchTaskExecutor` delegate + `Dispatchers.Main` surrogate (MangaScreenModelTranslationDrawerTest; sibling fixture `MangaScreenModelMultiSelectBatchTest` shares the same pattern per its own comment).
  3. `CrossOriginBitmapBudget` singleton (BatchParallelWindowBudgetTest — Before/After `resetForTesting`).
  4. `SeriesProfileRegistry` static state (ProviderHeadroomTest — Before/After clear).
Enabling **in-JVM concurrent execution** requires seaming (1) and (2) first; (3)/(4) are reset-guarded sequentially but are equally unsafe under overlapping methods.
- **Virtual time — scoped, not blanket (v2)**: none of the seven uses `runTest`. Virtual time with injected dispatchers/gates is a legitimate tool for semaphore/permit *logic* (e.g., `CrossOriginBitmapBudget` acquire/release ordering is drivable by a controlled scheduler). What must not be virtualized **as currently written** are the probes whose property IS real-thread behavior: `ChapterTranslationStatusOffMainThreadTest` (the probe only runs if the caller actually suspends on a real executor), the `delay(50)` negative observation in `BatchParallelWindowBudgetTest` (virtual time skips the real window it observes), and `TranslationSchedulerTraceTest`'s measured lease_wait. Migrating any of those requires redesigning the probe, not swapping the dispatcher.
- **Async cleanup — structured, but drain not exhaustively proven (v2)**: DrawerTest joins the cancelled scope *before* dismantling the ArchTaskExecutor delegate (`@AfterAll`, lines 261-289) with a documented rationale; coexistence harnesses close in `finally`; TraceTest restores all four globals in `@AfterEach`; OffMainThreadTest releases latches in `finally`. No unstructured leak was identified at source level in the seven, but this audit did **not** prove that every asynchronous publisher drains before a global restore (e.g., a collector still running on `Dispatchers.IO` after `restoreCapture` would emit into the restored sink). Treat drain-before-restore as unverified, not clean.
- **Skipped-test hygiene**: the only skip on disk is an asset assumption in an unrelated Paddle suite; no candidate uses assumptions/silent skips.
- **System property coupling**: `build.gradle.kts:580` sets `measurement.replayBench=true` for unit tests (gates `SyntheticJournalReplayBenchTest` via `@EnabledIfSystemProperty`). Unrelated to the candidates but part of the discovery surface; do not mistake its benches for purge candidates without checking the tag.

## 5. Revision log

- **v2**, in response to the primary cross-check:
  1. **WITHDRAWN**: the `evictCachedScreenModelScope` "operator-precedence/NPE defect" (§1 row 3). Kotlin's nullable-receiver `toString()` extension returns `"null"` for null receivers — no NPE path exists — and the predicate is intentional key-type breadth per its own comment. R3's NPE mechanism removed accordingly; residual exposure downgraded to conditional observability risk (best-effort reflection), priority P3.
  2. **Corrected parallelization model** (§0.4, §1 row 6, §2, R6): `maxParallelForks` spawns separate JVMs that do not share process globals — removed as a race trigger. The sharing triggers are in-JVM concurrent JUnit methods (externally injectable even with no in-repo config) and async publishers that outlive their test method; `@BeforeEach`/`@AfterEach` resets are explicitly **not** safe under overlapping methods.
  3. **Removed absolute "safe/clean" claims**: absence of in-repo parallel config ≠ universal safety (external property injection, async lifetimes); the async-cleanup audit is downgraded from "clean" to "structured, drain-before-restore not exhaustively proven".
  4. **R3 reworded**: `--tests` selects classes but cannot force cross-class order or fork layout; the full-suite task is the primary repro; forcing order requires an (uncommitted) launcher/suite config.
  5. **R5 reframed**: a fired retry warning evidences that a retry occurred — typed/environmental/intentional-transient causes are possible; it is not proof of nondeterminism.
  6. **ProviderHeadroom conclusion softened** (§1 row 8): "structurally forced" → "no race or deferral mechanism demonstrated in source; no-demonstrated-flake, not guaranteed-cannot-fail".
  7. **Virtual-time guidance scoped** (§2): semaphore/permit logic is testable under virtual time with injected dispatchers/gates; only the real-thread suspension probes (OffMainThreadTest, the delay(50) observation, TraceTest's measured lease_wait) must keep real-thread semantics as written.
  - **Unchanged**: the P1 replace verdicts and their verified live production contracts (`ChapterTranslator.kt:418-450`, `StandardLaneWorker.kt:338-351`), the no-deletion conclusion, and all other retain/repair classifications.
