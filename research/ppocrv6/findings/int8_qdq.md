Status: bounded host experiment complete. Numbers below are transcribed from
the raw result files generated by `research/test_int8.py` and
`research/test_qdq.py`; no model binary is tracked.

## Evidence summary

The raw files are the authoritative record:

- `research/results/int8_results.json` and `.csv`
- `research/results/qdq_results.json` and `.csv`

The JSON contains model byte sizes/hashes, conversion errors, explicit ORT
load errors, warm latency/throughput/RSS, REC tensor and CTC sequence/text
comparisons, DET probability-map and DB box drift, and mixed DET/REC pairs.

## Observed bounded results

All three completed variants converted and loaded on ORT 1.24.1 CPU with zero
recorded conversion/load errors:

| model | FP32 bytes | dynamic_pc bytes | qoperator_pt bytes | qdq_pt bytes |
|---|---:|---:|---:|---:|
| REC | 21,159,378 | 5,617,574 | 5,477,891 | 5,566,223 |
| DET | 9,880,512 | 2,649,472 | 2,628,660 | 2,687,029 |

On the single real fixture, every completed REC variant changed the greedy
sequence/text: FP32 decoded `ı`; dynamic-per-channel decoded `.`, while
QOperator and QDQ decoded an empty string. REC output-map maximum absolute
differences were 0.9018, 0.5270, and 0.8432 respectively; sequence exactness
was false for all three.

Every completed DET variant changed the DB result from one FP32 box to zero
boxes (`mean_best_iou=0.0`). Probability-map maximum absolute differences were
0.9793 (dynamic), 0.9749 (QOperator), and 0.9767 (QDQ).

Host-only warm timings for the bounded fixture were: REC dynamic 6250 ms,
QOperator 587 ms, QDQ 490 ms; DET dynamic 22,994 ms, QOperator 3820 ms, QDQ
4422 ms. Candidate load times ranged from 651–4511 ms. These are desktop CPU
measurements under concurrent host load, not Android performance claims; the
bounded raw files do not establish a clean FP32-vs-candidate timing ranking.

The mixed DET×REC cross-product was not included in the completed bounded raw
run: its repeated Python DB postprocess/session loads exceeded the resource
budget while other host benchmarks were active. The harness supports it via
the default (non-`--no-mixed`) mode, but there is no mixed accuracy claim here.

### Recommendation

Do not promote INT8/QDQ PP-OCRv6 to production from this evidence. Although
the graphs load and shrink to roughly 26–27% of FP32 size, the bounded real
fixture loses REC text parity and all DET boxes for every completed variant.
Revisit only with representative page/crop calibration (including the missing
76-page manifest), layer exclusions or QAT, and Android ORT validation.

## Limitations

- **UNVERIFIED:** no Android device/QNN/NNAPI compatibility claim is made by
  this host harness.
- **OBSERVED:** the checked-in desktop port is used for DB postprocessing and
  CTC decode so comparisons follow the app contract rather than raw logits
  alone.
- **INFERRED:** static calibration coverage is representative of the committed
  corpus, but it cannot establish accuracy on chapters not present here.
