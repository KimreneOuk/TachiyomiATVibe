## Fixture generation approach

`PlannedAnalysisChunk` / `AnalysisChunkPlanResult` are deliberately pure
(non-`@Serializable`) planner outputs and the fix is forbidden from touching
production files, so there is no production serializer to reuse (unlike the
envelope planner, whose `EnvelopePlan` artifact serializes through
`ArtifactDocumentJson`). The golden harness therefore owns a canonical
serialization: a stable test-local projection `canonicalPlanJson(...)` that
maps a `Success` plan to compact JSON with fixed field order
(`plannerVersion, chunks[chunkOrdinal, chunkId, corePageKeys,
contextOverlapPageKeys, contributingCorpusFingerprint, coreBlockCount,
contributingBlockCount, estimatedInputTokens, contributingBlockIds],
skippedTextlessPageKeys`) via `kotlinx.serialization.json` builders.

Bytes were generated by RUNNING that serializer: a scratch JUnit test
(`SCRATCH_AnalysisGoldenGeneratorTest.kt`, identical serializer + inputs)
planned the fixed corpus and wrote the encoded bytes directly to
`app/src/test/resources/t924/golden/analysis-chunks-small.json`. The JSON was
never hand-written or copy-pasted. The scratch test was deleted after the
bytes were frozen; the surviving test regenerates the same bytes in memory and
compares them byte-for-byte with the resource.
