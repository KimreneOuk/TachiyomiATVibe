## Interpretation

- `cold=1` includes fresh ONNX Runtime session creation as a separate `session_create` row; model invocation rows show cold first-use behavior after that creation.
- Decode lengths are fixed-step measurements: the loop continues after `[SEP]` so 5/10/20/40/80/128 each performs exactly that many token selections and cache steps. This isolates cost; production generation may stop early.
- `full_generation` includes the measured pipeline, while `decoder_step` and `token_selection` rows expose per-generation totals. Tokens/sec is retained in the CSV for generation rows.
- Memory is process RSS sampled around each operation and should be treated as an approximate upper-bound signal, not a model allocation trace.
- **UNVERIFIED:** Correlation with real manga crops, Android NNAPI/GPU/NPU providers, and end-to-end app latency requires device experiments.
