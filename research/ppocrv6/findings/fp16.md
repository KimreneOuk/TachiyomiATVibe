# PP-OCRv6 FP16 conversion and runtime findings

Status: research-only; no production model/assets were changed.

## Decision summary

**Do not approve FP16 DET for production yet.** The conversion loads and is about half the on-disk size, but detector box parity is not universally exact: the deterministic tensor probe changed 40 boxes to 44 (FP16 I/O) / 43 (FP32 I/O), with mean best-match IoU 0.9382 and an unmatched-box minimum IoU of 0.00016. The four real-page smoke pages were stable (8 FP16-vs-FP32 comparisons, equal box counts; worst mean matched IoU 0.99956, worst minimum 0.98684), but that is not a full corpus audit.

REC CTC text/sequence parity was exact for the four real annotated crops (8 comparisons) and all fixed tensor probes. Host CPU timing is backend-dependent: ORT FP16 was slower for REC, while OpenVINO FP16 I/O was faster for DET and FP16 keep-I/O was faster for REC. No Android device timing or Android RSS was measured.

## Corpus and scope

`research/dataset/manifest.json` inventories 3 chapters, 76 pages, and 486 annotated regions. The completed real-image run intentionally used a reproducible **4-page / 4-crop smoke subset** because the 76-page follow-up was stopped after resource pressure; the stopped run emitted no result file. Full-corpus parity is therefore **UNTESTED**, rather than extrapolated from the smoke subset.

Raw artifacts:

- [`research/fp16-results/results.json`](../fp16-results/results.json) and [`results.csv`](../fp16-results/results.csv): ORT, deterministic probes plus 4 pages/4 crops.
- [`research/fp16-results-openvino/results.json`](../fp16-results-openvino/results.json) and [`results.csv`](../fp16-results-openvino/results.csv): OpenVINO synthetic probes.
- [`research/test_fp16.py`](../test_fp16.py): conversion, load, parity, RSS sampler, timing, mixed DET/REC combinations, and optional manifest/page/crop inputs.

## Conversion and load

| model | FP32 bytes | FP16 I/O bytes | FP16 keep-I/O bytes | size reduction |
|---|---:|---:|---:|---:|
| DET | 9,880,512 | 4,973,761 | 4,974,139 | 49.7% |
| REC | 21,159,378 | 10,624,002 | 10,624,324 | 49.8% |

Converted hashes: DET FP16 I/O `2f0463ba51af55a9f49cae1f18cf905c578d4752236c30456325c817d8e47a1b`; DET keep-I/O `c7f5cf18ab6e64ee2e9835f1605b3c5a48d01ec41bf632637e2355ff89053d54`; REC FP16 I/O `f6ee9c86013fdd02cf9dfdf311813e1f2fe56e83d2b5f12994617dfa05d3b9cb`; REC keep-I/O `b19f8eb2d4cf78c4eeacbad27c03d658ffaff196e0c91591d894ec6482e0db64`.

The converter loads ONNX in memory so it never writes beside checked-in assets. `keep_io_types=True` needed a topological-order repair for ORT's inserted input Cast; ONNX checker then passed.

**CONFIRMED:** ONNX checker, ORT BASIC model load/inference, OpenVINO model load/inference, both conversion forms, and all four mixed combinations (FP32/FP32, FP16 DET only, FP16 REC only, both FP16) on deterministic probes.

**FAILED:** ORT `ORT_ENABLE_ALL` rejects converted REC during its optimizer with a missing `InsertedPrecisionFreeCast...` helper input. ORT results therefore use `ORT_ENABLE_BASIC`, consistently for FP32 and FP16. This is a runtime/backend compatibility failure, not evidence of numeric model failure.

## Parity

**CONFIRMED — REC:** CTC decoded sequence equality was 8/8 on the 4 real crops (both FP16 variants) and 8/8 on fixed tensor probes. This is exact sequence parity against FP32, not ground-truth accuracy.

**CONFIRMED but caution — DET:** All 8 real-page comparisons had equal connected-component box counts. One page had mean matched IoU 0.99956 and minimum 0.98684; the other three were exact under the harness threshold. The deterministic page-like tensor is an adverse/important counterexample: 40 FP32 boxes versus 44/43 FP16 boxes, mean best-match IoU 0.9382. Small score changes can cross DB thresholding/contour boundaries, so detector approval cannot be based on file size or mean tensor error alone.

**UNTESTED:** Full 76-page/486-region detection and full 486-crop recognition parity; Android/ARM execution; end-to-end production DB postprocess and OCR crop ordering across the full corpus.

## Warm host timing and RSS

These values are one short host run (`runs=1` for the final smoke output) under concurrent research load; use them for direction, not device commitments.

| backend / model | FP32 ms | FP16 I/O ms | FP16 keep-I/O ms | FP32 RSS peak | FP16 peaks |
|---|---:|---:|---:|---:|---:|
| ORT / DET | 7,890.6 | 6,035.7 | 5,899.1 | 493 MB | 501 / 510 MB |
| ORT / REC | 779.8 | 1,200.1 | 1,347.2 | 1,024 MB | 1,051 / 1,051 MB |
| OpenVINO / DET | 3,039.9 | 2,194.6 | 3,055.8 | 460 MB | 469 / 464 MB |
| OpenVINO / REC | 396.8 | 465.3 | 319.8 | 798 MB | 803 / 801 MB |

ORT suggests DET speedup but REC slowdown. OpenVINO differs, with FP16 I/O DET and FP16 keep-I/O REC faster in this host run. RSS did not decrease; process RSS includes runtime caches and graph/session allocations, so FP16 storage reduction must not be described as a runtime-memory win.

## Labels and recommendation

- **CONFIRMED:** conversion size/load, fixed tensor output parity, REC exact sequence parity, four real-page/crop smoke parity, host timing/RSS, and mixed-combination execution as described above.
- **LIKELY:** FP16 may reduce packaged model storage and can speed DET on some host backends; this is backend/device-specific.
- **UNTESTED:** full manifest quality, Android ARM latency/RSS, battery/thermal behavior, and production reader stability.
- **FAILED:** ORT ALL optimizer path for converted REC; the 76-page follow-up was resource-limited and is not a valid result.

Recommended next gate: run the same harness on the target Android ORT/OpenVINO path with the complete 76-page/486-region manifest, report DB-postprocessed box count/IoU and crop order, and only then consider FP16 DET. REC should remain FP32 on ORT unless target-device measurements reverse the observed host slowdown.
