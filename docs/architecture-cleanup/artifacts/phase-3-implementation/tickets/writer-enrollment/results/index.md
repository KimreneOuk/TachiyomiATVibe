# Interpretations and intentional deviations (per child-agent report duty)

1. Guard predicate: `!hasArtifactPersistenceTarget()` exactly as the approved ownership-options sketch pins (the `scheduleDrain` refusal predicate). This CHANGES behavior for stores without a persistence target: enqueue now rejects with an immediate receipt-false instead of queueing a task only an explicit `flush()` could ever run. Production callers always enroll on targeted stores; the two affected test fixtures were upgraded deliberately (fixture honesty — a no-target fixture can no longer exercise queued-task paths).
2. Defunct test restructured: with an active scheduled drain, the old scenario (queue a task, markDefunct before any drain) is unreachable — `markDefunct`'s bounded join lets the debounced drain fire first and run the work. The test now covers the two real defunct paths deterministically: the ACTIVE worker is cancelled cooperatively (bounded join, then drain cancel → receipt false), and a QUEUED second task is discarded by `releaseRetainedCreditsLocked` without starting (receipt false). Same discard-before-write guarantee, reachable mechanics, virtual-time deterministic.
3. Store-exclusivity is caller-side contract discipline (documented in KDoc), not an enforceable store-side state: a queued-but-uncompleted receipt can technically be completed by its holder. The test asserts the enforceable no-op-after-store-completion property. First implementation attempt asserted the impossible (`complete` before flush returned true) and is retained as failed attempt 3.
4. WITHDRAWN (per parent protocol correction on thread `ff378402`): an earlier revision of this artifact claimed a cancellation window between `owner.registerReceipt(receipt)` and NC-enqueue entry. That claim was WRONG and is retracted: synchronous non-suspending `registerReceipt` immediately followed by `withContext(NonCancellable)` has NO cooperative-cancellation suspension point between them — an already-cancelled caller still enters the NC block and enqueues, so the receipt always terminates once registration is reached. No caller-side `complete(false)` is prescribed anywhere; the approved synchronous registration + narrow NC enrollment protocol stands unchanged. Review scope note recorded: in S2 the receipt lives inside the callee until returned; cancellation-on-return and local recycle safety are part of the reviewer's actual-diff assessment, not gated on the owner being unwired.
5. `receipt.complete` inside a finally: Kotlin/ktlint-clean; the finally path runs on cancelled callers too (completing a Deferred is non-suspending).
6. Launch preflight policy (parent, standing): the NEXT justified launch must fail fast BEFORE Gradle on (a) pre-created empty evidence dir present, (b) exact init filename the guard resolves (`s1-runid-init.gradle`), (c) guard script executable — implemented as mechanical preflight in the launch command, not a remembered checklist.
