## Confirmed foundations

- **VERIFIED:** Whole-page unfinished, nonblank text is buffered; already translated non-source-equal blocks are excluded. Admission flushes on token overflow, or a rejected block/page; exhaustion flushes the tail. No block/page batching cap exists (`translator/contextual/StreamingChunkPlanner.kt:83-155`). Thus “only overflow” is useful shorthand, not an exhaustive exit description.
- **VERIFIED:** AI admission stores emissions and returns PROBE for a nonnull emitted chunk (`pipeline/batch/BatchLaneWorkers.kt:1436-1453`). The coordinator retains that incoming page for the next chunk without admitting it twice, releases the OCR barrier, then processes the prior chunk (`pipeline/batch/SequentialBatchCoordinator.kt:617-690`). The barrier drains pending emissions sequentially; only the final chunk flushes the planner tail (`pipeline/batch/BatchLaneWorkers.kt:1639-1671`). These substantiate the established latency diagnosis without independently proving the observed page count or timeout rate.
- **VERIFIED:** Input estimate is 1,400 plus per-block `tokens(pageKey)+8+tokens(text)`; default ceiling is 8192, safety 512, minimum output 256. Response reserve is **34 + 24×pages + 8×blocks**, not merely eight per block. LM Studio ceiling is 16,000. Rolling/glossary allowance is 1500 default, 1024 LM Studio; glossary is dropped first, then all rolling context if still over budget (`translator/contextual/StreamingChunkPlanner.kt:194-222,244-253`; `translator/contextual/TranslationContextChunkPlanner.kt:21-39,92-120,143-148,179-202`). CL100K is an estimator for this budget, not proof of every provider's exact token count.
- **VERIFIED:** Force reuse currently couples OCR and inpaint readiness, while non-force calls evidence planning without expected fingerprints (`model/PageWorkPlanner.kt:20-58`). Missing expectations make fingerprint matching pass (`model/PageWorkPlanner.kt:275-287,366-371`). The reuse gap stands, but a promised **fingerprint-validated force fix needs an evidence/input design**, not just changing `&&`: the current API accepts no expected source/config fingerprints. Batch planning does supply them (`pipeline/batch/BatchResumePlanner.kt:91-108`).
- **VERIFIED:** Frontier seeding requires reusable/terminal planning evidence; PARTIAL cannot advance context and terminal non-textless gaps fence later AI (`pipeline/batch/BatchResumePlanner.kt:123-174`; `pipeline/batch/BatchContextFrontier.kt:34-90,106-108`).
- **VERIFIED:** OCR acquires a BATCH lease and records deferral on denial; references retain lease/candidate/dependency identity (`pipeline/batch/BatchLaneWorkers.kt:824-855,1292-1303`). OCR merge checks generation, page/artifact versions, candidate/dependency, prior OCR identity, and lease; publication failure restores prior state (`ChapterTranslationStore.kt:826-861,922-928`). Display promotion requires rendered or textless-terminal shape and copies the page, retaining superseded cleaned names (`ChapterTranslationStore.kt:1888-1910`). Durable OCR publication and committed display are distinct concepts.
- **VERIFIED:** Render awaits both branch gates; native handoffs release in finally; both branch jobs finish before the next chunk (`pipeline/batch/SequentialBatchCoordinator.kt:194-249,560-613,688-695`). Batch teardown releases/cancels leases and flushes under NonCancellable (`pipeline/batch/BatchChapterTranslator.kt:769-795`); outer trace closes in finally even if teardown throws (`:203-253`). The later retention/callback operations are sequential and can be skipped by a preceding exception, so “every exit runs all cleanup operations” is stronger than source guarantees.

## Refinements needed before converging

1. **CONTRADICTION / ambiguous table:** SHIP_ALONE overlaps both overflow rows when `pageBlocks > cap`. Specify precedence and behavior with a nonempty under-minimum buffer. “Always ships alone” and “avoid crumbs by admitting the large page with the small buffer” cannot both hold for that input.
2. **STRONG INFERENCE:** Immediate post-admission emission cannot be added casually. The worker interprets every nonnull chunk emission as the incoming page being a PROBE for the next chunk. If that emission contains the incoming page while a prior coordinator chunk exists, planner envelope membership and coordinator stage ownership diverge (`BatchLaneWorkers.kt:1445-1453`; `SequentialBatchCoordinator.kt:672-684`). A first-envelope threshold and oversize-single-page behavior must preserve this pre-check handoff or explicitly extend the contract. Current `Emission` exposes only the last chunk; the lane does not consume `emittedChunks()` (`StreamingChunkPlanner.kt:26-34,143-159`). Avoid two flushes in one accept under this interface.
3. **ASSUMPTION:** 30–40 blocks, ~15 minimum, 3–4 first pages are reasonable tuning candidates, not measured latency/quality bounds. Define blocks as pending nonblank request blocks to match pricing, and define which pages count for the first-envelope rule. Block counts alone do not bound OCR pages/time when pages contribute no request blocks.
4. **CONTRADICTION:** A universal “no crumbs below minFill” test conflicts with final tails, hard token overflow, rejected pages, and potentially the adopted small-first-envelope exception. Tests should explicitly permit those boundaries. Never apply minimum-fill by overriding token admission.
5. **UNKNOWN until implementation/test:** “Zero risk” buffered UI, “confined to planner plus preference,” and unconditional safety preservation are design objectives rather than established facts. Boundary tests must cover exact cap/minimum equality, token precedence, probe not double-admitted, oversized incoming page with empty/small/full buffer, first-envelope handoff, resume/textless pages, tail, pause/cancel, and render/lease settlement. Preserve the chosen direction; settle admission semantics first.

Recommendation: discuss cap/minimum and first-envelope admission semantics together before deciding preference UX or deferred OCR overlap. No design/README changes made pending Director convergence.
