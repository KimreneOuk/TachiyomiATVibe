## Proposed one context API

Introduce a typed `ChapterContextService` owned by the existing chapter store/session, not a second global writer. Its operations are:

1. `replaceCommittedPageContribution(pageKey, revision, sourceFingerprint, authority, compactPairs)` under the store mutex; idempotent by revision and replacing, never additive on retranslation. Only accepted committed results enter the durable evidence model. UI rendering/PARTIAL output does not promote evidence.
2. `publishAnalystEvidence(validatedChunkEvidence, provenance)` through the existing durable publication boundary. Analyst remains optional and source-grounded; no synchronous analyst request on a manual tap or auto page.
3. `prepare(ContextRequest)` returns an immutable `PreparedContext` and `BudgetDecision`. Request includes chapter/source identity, target language, request page/block IDs, natural range/proof, lane capability, frozen run identity and provider framing contract. Return includes selected typed facts, bounded predecessor pairs, unresolved/conflict state, rendered payload, selected-evidence digest, policy versions, input accounting, output cap and typed omission reasons.
4. `snapshotForRun` pins analyst base and policy; evolving committed observations are separate versioned overlays. An envelope snapshots once before dispatch/retry, and its provenance describes the exact selected context. Manual and auto use the same selector with a page-local predecessor range. Existing gap fencing remains a separate eligibility constraint, not something context selection bypasses.

Producers: user lexical choices, source-grounded analyst facts, heuristic recurring output mappings, committed recent pairs. Consumers: manual contextual, auto contextual, profile AI batch all invoke the same prepare/render/allocate path; standard engines invoke a capability adapter returning no prompt context and preserve existing translation behavior. The shared service does not require identical protocol shape: LEGACY and BATCH_V1 response parsers remain intact.

Typed record minimum: stable ID; kind (lexical rendering/entity alias/source gender/scene/prior pair); source and target language; canonical source form; evidence references with OCR revision/hash; page range; producer/provenance version; confidence/status; target text where applicable; replacement/tombstone revision. Rendering must label target-derived mappings as previous choices, not facts about identity or gender. OCR/LLM content remains quoted data, not instructions.

Merge: (a) explicit user lexical choices win lexical rendering within their scope; (b) validated source evidence resolves identity/gender, but contradictory source evidence yields CONFLICTING rather than winner-by-time; (c) analyst aliases and scoped facts outrank heuristic output mappings for those same identities; (d) consistent repeated output only suggests lexical continuity; (e) recent pairs guide voice/local discourse and never establish gender. A manual-authoritative page is protected output authority, not proof that every inferred story fact in it is true. Do not globally substitute aliases or scene words. Scope conflicts are resolved by most specific applicable range only when the assertions are compatible; otherwise carry a compact conflict marker. Deterministic tie order: relevance to requested sources, evidence quality, proximity, stable ID.

Rolling-first is not recommended. Reserve small space for directly relevant lexical/entity decisions plus uncertainty, then nearby source/target pairs, then optional scene prose. Never evict all stable name choices merely because one pair is long. Never trim inside a fact/pair into misleading text; omit whole records and record omission metrics. Global identity/source-gender rules belong in fixed instructions, so trimming cannot remove them.

## Proposed 8192 allocator and proof obligation

One allocator applies to translation, legacy-shaped profile requests, analysis, and retry requests. Let I be the final model input including system instructions, examples, context headings, IDs, separators, JSON escaping and provider/model chat template. Let O be the actual max-output parameter, including response syntax; let S=512 be operational reserve. Admission requires I + O + S <= 8192. O is the whole output, so response delimiters must NOT be counted again outside O. No unconditional output floor after rejection. If remaining budget cannot support a useful complete-page response, split at whole-page boundaries and rebuild; if one page cannot fit, typed oversized PAUSE. Analysis needs the same no-send behavior; it must not admit an oversized single page because its planner window was empty. Block splitting remains a Director-gated choice.

Concrete translation example (PROPOSAL, illustrative exact counts under a certified counter): instructions/template 1400 + source/IDs/escaping 3000 + selected context 800 = I 5200; O 2480; S 512; total 8192. For 3 pages/12 blocks, current deterministic BATCH framing allowance is 32 + 2 + 24*3 + 8*12 = 202 tokens (`TranslationContextChunkPlanner.kt:179–185`). Thus O=2480 leaves 2278 for translated text. Context allocation within 800 could be relevant names/identity 320, unresolved safeguards 96, recent pairs 288, local scene 96; unused slices flow to remaining relevant records. These are soft selection preferences, never extra budgets. If measured fixed framing exceeds 1400, shrink selection or page grouping; do not pretend it still equals the constant.

Dense single-page example: I_without_context=6000, O_minimum_required=2000, S=512 => 8512, reject even with context empty. Shrinking output to 256 would satisfy arithmetic but fail the intended complete translation. Output reserve should derive from source expansion and response structure, calibrated by language with an explicit minimum and ceiling. The user-selected output setting is an upper bound; insufficient output budget yields a typed decision, not silent truncation.

Analysis example: actual instructions/template 1100 + source evidence JSON 3600 + already-established facts 400 = I 5100; O 2580; S 512 =8192. Unlike translation, O reserves structured evidence fields/citations, so independently validate output-size planning. Overlap pages consume the 3600 pool; shrink overlap before shrinking core, with a new fingerprint when planning changes. Numbers from EXECUTION_ORDER (4096/3584 envelope, 4608/3072 analysis) are provisional input/output policy values, not proof: 4096+3584+512 already exhausts 8192 before additional 1400 overhead if 4096 means source-only.

CRITICAL: CL100K_BASE estimate plus 512 is not a proof for arbitrary models. Require a provider `InputAccountingContract`: certified exact model/template counter, or a certified conservative upper bound over final rendered model input. A provider-side count endpoint is usable if bounded and tied to the same model/template revision; cache only immutable framing/tokenizer metadata and current bounded request counts, not chapter text. Do not load one large tokenizer per provider into RAM. If neither contract exists, mark token accounting unsupported and do not send that model request under the all-model guarantee; provider-side strict rejection with a documented no-truncation 8192 context can enforce safety but is not evidence that a request fits before dispatch. A byte-based ceiling is usable only with a proved model-specific upper bound and bounded hidden template overhead, never assumed universal. Expose this compatibility issue as a design prerequisite, not a user preference to weaken the limit. Unknown: availability of certified counting/template metadata for every currently selectable backend; requires provider adapter audit before implementation approval.

## Bounded memory and work

Do not represent 200 pages as 200 resident images or duplicate full PageTranslation objects in this service. Stream committed OCR/text evidence from existing checkpoints; keep a current request, a fixed-byte recent-pair ring, and compact indices. Proposed initial limits for profiling: recent pairs <=32 AND <=16 KiB UTF-8; selected fact serialization <=16 KiB before token selection; one prepared request <=64 KiB. A single long pair is omitted rather than truncated. These are explicit quality-affecting proposed limits and require multilingual/long-bubble tests; they are not claimed current behavior.

Exact recurrence counts with arbitrary unique terms cannot coexist with a constant-size in-memory map and unlimited chapter input. Preserve exact semantics by storing page contribution records and aggregate counts in a bounded-memory disk-backed index, with replace/subtract operations and a maintained ranked candidate index; do not seed from the top 30 or silently evict rare terms. Use existing artifact boundaries for authoritative page contributions; the index is rebuildable, streamed one page at a time after corruption/crash. A purely in-memory first slice may bound itself by an explicit supported corpus size, but this is not a general bounded-memory solution. If disk-backed indexing is too large a scope, retain exact streaming recomputation on demand as a slower fallback and state its O(chapter text) cost. Incremental `add` with current `build()` still has candidate-history scanning/sorting. An O(B) claim requires incremental ranking/eligibility updates as well, and ranked lookup likely gives O(B log C), not O(B), for C distinct candidates.

Do not silently change recurrence/scoring for memory savings. A hard chapter evidence byte/page limit is a product constraint requiring explicit review; 200 pages alone does not bound text size. Bitmap budget remains a separate cross-origin prerequisite in EXECUTION_ORDER.

## Reuse, frozen runs, and cost semantics

Separate analyst input fingerprint, semantic evidence content revision, selected prompt digest, allocator/prompt policy version, and existing render/output authority stamps. A single chapter version cannot distinguish unrelated new evidence from a changed fact actually used by a page. Retain the existing fold-then-live-glossary stamp compatibility mechanism until an independently reviewed reuse migration; never repurpose it as exact request provenance. New selected-context digest describes what the model saw; commit evidence revision describes what became durable later.

Freeze the analyst base for a run; permit committed predecessor overlay at envelope boundaries with selected digest. This preserves stable analysis while enabling local continuity. Do not claim byte-identical frozen prompts if overlay evolves. A new analyst profile while a run is active becomes eligible at a new run boundary; a direct user correction still follows existing authority/fence policy. Source changes invalidate matching evidence references and derived contributions, not blindly every rendered chapter page.

“Paid once per chapter” can mean no extra analyst call per translated page and reusable validated analysis for the same corpus/configuration. It cannot mean one request: chunking makes multiple calls, every translation transmits selected context again, stale input may require reanalysis, failed attempts cost requests, and a provider response lost before durable commit may be billed but unusable. Existing durable chunk-prefix resume reduces repeat work; it does not prove exactly-once remote billing. Do not add unapproved automatic restart or launch resume to solve this.
